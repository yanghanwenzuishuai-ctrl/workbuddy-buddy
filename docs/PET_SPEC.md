# workbuddy-buddy — Pet Design Spec

Design and drop in your own pet. A **pet pack** is just two files:

```
pet.json           # manifest (states, grid, animation timing)
spritesheet.png    # one transparent PNG holding every frame
```

The built-in reference pet (`frontend/pet/`, generated by `assets/gen_sprite.py`)
is the canonical example — copy it and edit.

---

## 1. The 7 states

The pet reflects WorkBuddy's live status. Your spritesheet must provide an
animation row for **each** of these state names (they are the exact keys in
`pet.json.animations`):

| # | state | color idea | shows when… | what WorkBuddy is doing |
|---|-------|-----------|-------------|-------------------------|
| 0 | `idle` | calm blue | session start / no activity for a while | doing nothing |
| 1 | `thinking` | indigo | right after you send a prompt | reasoning about your request |
| 2 | `working` | amber | a mutating tool runs (Write/Edit/Bash…) | changing things |
| 3 | `review` | teal | a read-only tool runs (Read/Grep/Glob…) | just looking |
| 4 | `waiting` | purple | permission prompt / agent finished & idle | **waiting for you** |
| 5 | `done` | green | the turn completed | finished |
| 6 | `failed` | red | an error notification | something broke |

**Arbitration & decay** (handled for you by the app):
- With multiple sessions live, the pet shows the highest-priority state:
  `failed > waiting > working > review > thinking > done > idle`.
- Active states (`thinking`/`working`/`review`) fade to `idle` after 3 min with
  no new events; `failed` after 1 h, `waiting` after 24 h, `done` after 7 days.

You don't have to make all 7 visually distinct, but the more distinct they are,
the more useful the pet — the whole point is a glanceable status.

## 2. Spritesheet layout

A single transparent PNG (or WebP), laid out as a grid:

```
        col 0    col 1    …    col 7      (COLUMNS frames per state)
row 0 [ idle f0 ][ idle f1 ]…[ idle f7 ]
row 1 [ think f0]…                        (one row per state, in the order above)
row 2 [ work …  ]
row 3 [ review… ]
row 4 [ wait …  ]
row 5 [ done …  ]
row 6 [ fail …  ]
```

- **Cell size**: any consistent `width × height` (reference uses **192 × 208**).
- **Columns**: any `N` frames per row (reference uses **8**). More frames = smoother animation.
- **Rows**: one per state. Row order is **defined by `pet.json`, not by position** —
  each animation names its own `row`, so you may order rows however you like as
  long as `pet.json` points to the right one.
- Background **must be transparent** — the window is transparent and the pet floats.
- This is the same grid convention as Codex Pets, so most Codex/`pet.json`
  spritesheets are compatible after adjusting the animation keys to the 7 names above.

Frame at `(row, frameIndex)` is drawn from pixel rect
`x = (frameIndex % columns) × width`, `y = row × height`.

## 3. `pet.json` schema

```json
{
  "id": "my-cat",
  "displayName": "My Cat",
  "description": "A grumpy cat that judges your code.",
  "author": "you",
  "license": "CC-BY-4.0",
  "spritesheetPath": "spritesheet.png",
  "frame": { "width": 192, "height": 208, "columns": 8, "rows": 7 },
  "animations": {
    "idle":     { "row": 0, "frames": [0,1,2,3,4,5,6,7], "fps": 6,  "loop": true },
    "thinking": { "row": 1, "frames": [0,1,2,3,4,5,6,7], "fps": 10, "loop": true },
    "working":  { "row": 2, "frames": [0,1,2,3,4,5,6,7], "fps": 12, "loop": true },
    "review":   { "row": 3, "frames": [0,1,2,3,4,5,6,7], "fps": 10, "loop": true },
    "waiting":  { "row": 4, "frames": [0,1,2,3,4,5,6,7], "fps": 5,  "loop": true },
    "done":     { "row": 5, "frames": [0,1,2,3,4,5,6,7], "fps": 8,  "loop": true },
    "failed":   { "row": 6, "frames": [0,1,2,3,4,5,6,7], "fps": 4,  "loop": true }
  }
}
```

| field | required | meaning |
|-------|----------|---------|
| `id` | ✓ | short unique slug |
| `displayName` | – | human name (shown in future pickers) |
| `description`, `author`, `license` | – | metadata; **set `license`** if you share |
| `spritesheetPath` | ✓ | path to the PNG, relative to `pet.json` |
| `frame.width` / `frame.height` | ✓ | cell size in px |
| `frame.columns` | ✓ | frames per row (used to compute the source x) |
| `frame.rows` | – | informational |
| `animations` | ✓ | one entry per state (all 7); each: |
| &nbsp;&nbsp;`row` | ✓ | which grid row (0-based) |
| &nbsp;&nbsp;`frames` | ✓ | frame indices to play, e.g. `[0,1,2,3]` |
| &nbsp;&nbsp;`fps` | – | playback speed (default 6) |
| &nbsp;&nbsp;`loop` | – | `true` loops; `false` holds the last frame |

Minimum to render: valid `frame` dims + a `spritesheetPath` + at least an
`idle` animation. Missing states fall back to `idle`, so you can start with one
row and grow — but a real pet should define all 7.

## 4. The buddy library & picker

The app ships a **library** of buddies under `frontend/pets/<id>/` — each a pet
pack (`pet.json` + `spritesheet.png` + a small `preview.png`) — listed in
`frontend/pets/index.json`:

```json
{ "default": "sora-shiba",
  "pets": [ { "id": "sora-shiba", "displayName": "Sora Shiba", "description": "…" }, … ] }
```

Switch buddies from the **menu-bar tray → 选择伙伴 / Choose buddy…**, or by
**double-clicking the pet**. Your choice is remembered across restarts
(localStorage). The `default` in `index.json` is used on first run.

### Add your own buddy
1. Build a pack per §2–3 (`pet.json` + transparent `spritesheet.png`).
2. Make a thumbnail: crop the idle frame (top-left cell) and scale to ~120×130 → `preview.png`.
3. Drop the folder into `frontend/pets/<your-id>/` and add an entry to
   `frontend/pets/index.json`.
4. Rebuild the desktop app (or, in the browser/bridge build, just reload) — your
   buddy shows up in the picker.

`assets/import_pets.py <src-dir>` does steps 2–3 for a whole folder of packs
(validates dimensions/states, generates previews, rebuilds `index.json`).
Runtime drop-in from `~/.workbuddy-buddy/pets/` (no rebuild) is a planned convenience.

## 5. Design guidelines

- **Transparent background**, centered subject, a little breathing room around edges.
- **Readable at ~120–180 px** — the pet is small on screen. Bold silhouette, high contrast.
- **One glanceable difference per state** — color is the fastest signal; add an
  expression/prop (`?` for waiting, sparkle for done, X-eyes for failed).
- **2–8 frames** of gentle motion (bob, blink) reads as "alive" without being noisy.
- Keep `waiting` and `failed` the most eye-catching — those are the ones you must notice.
- **Privacy**: pets are pure art; they receive only the current state string,
  never any of your conversation or command data.

## 6. Validation checklist

- [ ] `pet.json` parses; `frame.width/height/columns` present
- [ ] all 7 animation keys exist (`idle thinking working review waiting done failed`)
- [ ] each `row` is within the sheet; each `frames` index `< columns`
- [ ] PNG background is transparent
- [ ] each state is visually distinguishable at small size
- [ ] a `license` is set if you plan to share it

## 7. Reference

`assets/gen_sprite.py` generates the built-in pet procedurally and is the
executable source of truth for this format — read it for exact geometry, or run
it to regenerate `frontend/pet/`.
